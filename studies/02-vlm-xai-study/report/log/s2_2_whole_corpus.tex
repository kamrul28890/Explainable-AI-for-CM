\chapter{Every Compliant Image, Not Only the Sampled Ones}
\label{chap:s2-2}

\section{Goal}

The Stage~1 sample is deliberate (architecture document \S5.3): all 1,278 images with an annotated violation
and 1,278 compliant images matched to them, 3,882 (image, rule) questions in all. That left 7,457 compliant
images the model never saw. Specificity measured on the matched stratum is only as good as the matching, so
this phase asks the model about every one of them.

\section{What Was Done}

\texttt{01\_build\_sample.py -{}-complement} writes \texttt{complement\_manifest.csv}: one row per unsampled
compliant image, stratum ``R'', with the rule asked chosen by the same \texttt{rules\_to\_ask} logic as the
main sample (one rule per image, as before). The manifest was built locally first (7,457 rows, SHA-256
\texttt{cccec48c\ldots}); Scholar rebuilt it and the chain refused to start unless the hash matched, which it
did byte for byte. Stage~2 then ran on it in a separate chain, writing
\texttt{baseline\_qwen7b-4bit\_complement.csv}, so the frozen sample files are untouched.

\section{Problems and Solutions}

None at run time. The one design choice --- a single rule per unsampled image rather than all applicable
rules --- was kept from the main sample so the two strata are comparable; asking every applicable rule would
have roughly doubled the run for a different estimand.

\section{Standard vs.\ Non-Standard Choices}

\textbf{Standard.} Validating a stratified sample against the population it represents.

\textbf{Non-standard.} Hash-gating the manifest across machines, so the cluster run provably asked the
questions that were built and reviewed locally.

\section{Implications}

The study sample does not flatter the model: specificity is about 43\% whichever compliant images are used.
rule\_3 is the extreme --- on 93\% of compliant questions the model reports a violation --- and the paper
should state it per rule, since the pooled false-alarm rate hides a range from 8.5\% to 93.2\%.
