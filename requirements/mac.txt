# WHAT THIS MACHINE IS FOR
# ------------------------
# On an 8 GB M1 this is the DEVELOPMENT and ANALYSIS machine, not the compute
# machine. Model inference stages run on the CUDA box (see docs/setup/SETUP.md
# section "Which machine runs what"). Here you edit code, inspect the dataset,
# compute statistics from committed CSVs, build figures, and write.
#
# WHY NOT RUN THE MODELS HERE
# ---------------------------
#   * bitsandbytes has no Apple Silicon build, so the 4-bit/8-bit quantisation
#     the study specifies cannot be reproduced.
#   * MLX can run quantised Qwen2.5-VL, but does not expose per-layer attention
#     or image-token ablation -- which would silently drop Sparsity (metric 2)
#     and the artefact-free masking the design depends on.
#   * The M1 GPU is roughly 5-8x slower than the RTX 3070 for this workload,
#     turning a ~60 h study into months of runtime.
#   * 8 GB unified memory is shared with the OS. A 3B model in fp16 needs about
#     6.6 GB and will swap.
#
# MLX is included anyway so small smoke tests and prompt iteration are possible
# locally before committing a long run to the CUDA machine.

# Apple's Metal array framework and its VLM wrapper.
mlx>=0.18; platform_system == "Darwin" and platform_machine == "arm64"
mlx-vlm>=0.1; platform_system == "Darwin" and platform_machine == "arm64"

# torch on macOS comes from the default PyPI index and includes MPS support.
# No index-url needed, unlike the CUDA build.
torch>=2.4; platform_system == "Darwin"
torchvision>=0.19; platform_system == "Darwin"
